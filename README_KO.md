# S.O.R.T. 5 — 서울 5개 미션 웹 플레이테스트

## 실행 방법

이 폴더는 **로컬에서 직접 실행하는 웹사이트 소스**입니다. 배포된 공개 URL이 아닙니다.

### 1. 설치 (Python 3.10 이상)

```bash
cd sort5_seoul_web
python -m pip install -r requirements.txt
```

### 2. 서버 실행

```bash
python -m uvicorn server:APP --host 0.0.0.0 --port 8000
```

### 3. 브라우저에서 열기

- 서버를 실행한 컴퓨터: `http://localhost:8000`
- 같은 Wi-Fi에 연결된 다른 기기: `http://[서버 컴퓨터의 내부 IP]:8000`
- 서로 다른 장소에서 4명이 플레이하려면 서버를 접속 가능한 환경에 **별도로 배포**하고, 안전한 HTTPS 접속을 구성해야 합니다. 이 ZIP에는 호스팅이나 공개 URL이 포함되어 있지 않습니다.
- 인터넷으로 공개하기 전에 인증/속도 제한/방 관리/운영 보안 검토가 필요합니다. 운영용 서비스가 아니라 게임 규칙 검증용 프로토타입입니다.

### 4. 플레이

1. **Create room**에서 닉네임, 서울 미션 01~05, 사람 수(1~4명)를 고릅니다.
2. 2~4명이 함께 할 경우 방 코드를 공유하고 다른 기기/브라우저에서 **Join room**으로 입장합니다. 모자란 자리는 AI로 채웁니다.
3. 방장이 **Deal cards and begin**을 눌러 카드를 나눠줍니다.
4. 각자 자신의 패를 확인하고 **캐릭터**를 선택합니다. 캐릭터는 중복 선택할 수 없습니다. 나머지 캐릭터는 AI에게 배정됩니다.
5. 서울 02는 각자가 공개할 카드를 선택합니다. 서울 03은 **패를 보기 전에 서버가** 무작위로 공개 카드를 정해 둡니다.
6. 시작 카드를 받은 ▲ 플레이어가 첫 턴을 시작합니다.
7. 자기 카드 클릭 → 다른 플레이어 클릭 → **Pass selected card** → 수신자는 시간 칩을 사용해 **Green / Red**를 표시합니다.
8. 세트를 완성하면 자동 공개 및 퇴장합니다. 성공 후 다음 서울 미션으로 진행할 수 있습니다.

## 지원 방식 및 구현 범위

- 사람 1+AI 3 / 사람 2+AI 2 / 사람 3+AI 1 / 사람 4+AI 0
- 실제 각 브라우저가 **서로 다른 플레이어 시야**를 가지는 서버 기반 방 시스템
- 정보 카드 20장+시작 카드 1장, 서버 섞기·배분
- 미션 02, 03의 준비 효과
- 카드 공개 유지, 특정 캐릭터 공개 전달
- 시간 칩 초록/빨강 피드백, 카드 수신자 턴 전환
- 다섯 장의 같은 색 1~5 세트 판정, 완료자 탈락과 남은 칩 상실
- 마지막 남은 플레이어의 즉시 공개와 전체 성공/실패 판정
- 각 플레이어 손패 비공개; 서버가 상대의 비공개 카드 ID를 보내지 않음
- 테스트 모드에서 **방장만** 다른 캐릭터 시야를 별도 탭으로 확인 가능(게임 정보가 노출되는 개발 테스트 기능)
- 승리 후 다음 서울 미션/패배 후 재도전

## 정확도·제한 사항

1. **시작 카드 수신 시 시간 칩:** 룰북의 카드 수신 규칙에는 시작 카드 예외가 없습니다. 이번 임시 구현은 시작 카드를 받을 때 **부정(빨강) 시간 칩 1개를 자동 소모**합니다. 출판사 확정이 필요합니다.
2. **시간 칩 0:** 미션 완료 전에 마지막 시간 칩을 소모하면 즉시 실패로 처리했습니다. 최종 플레이어가 도착 카드로 마지막 세트를 완성한 경우엔 우선 즉시 공개·완료 판정을 적용했습니다.
3. **긍정/부정:** 게임의 '필요한 카드'는 플레이어가 전략적으로 정하므로 초록/빨강 선택은 플레이어가 합니다. 서버는 색상 목표를 마음대로 강제하지 않습니다.
4. **AI 수준:** v0.7에서 목표 색상을 매 턴 재평가하고, 공개 카드·직접 관찰한 카드·시간 칩·피드백을 활용하도록 개선했습니다. 여전히 휴리스틱 기반이며 높은 승률을 보장하지 않습니다. 상세 내용과 AI 4인 시뮬레이션 결과는 `AI_UPDATE_KO.md`를 참고하세요.
5. **실시간 방식:** 페이지가 약 1.5초마다 서버 상태를 갱신하는 **폴링**으로 동기화합니다. 웹소켓 기반 고성능 실시간 서버는 아직 아닙니다.
6. **채팅 없음:** 플레이 중 손패를 직접 말하지 말라는 규칙을 위하여 게임 내 채팅을 넣지 않았습니다. 외부 메신저/음성 대화는 서버가 통제하지 않습니다.
7. **호스팅 미포함:** 프로젝트는 메모리에서 방을 관리합니다. 서버가 재시작하면 게임 방이 초기화됩니다. 한 개 서버 프로세스로 실행하세요(다중 워커 미지원).
8. **검증:** 서버 자동화 테스트 46개 통과. 이 환경의 브라우저 접근 제한으로 Chromium UI 자동 E2E 테스트까지 완료한 상태는 아닙니다. 실제 기기에서 조작 확인이 필요합니다.

## v0.2 업데이트 — AI 턴 수동 진행 / 시간 칩 피드백 가시화

- AI 플레이어 차례에는 **AI 턴 진행하기 (1회)** 버튼이 나타납니다. 버튼을 한 번 누르면 카드 전달이 한 번만 일어납니다. AI끼리 이어지는 턴도 자동 진행되지 않습니다.
- AI가 카드를 받은 경우 칩 반응(초록/빨강)은 같은 단계에서 표시됩니다. 사람이 카드를 받았다면 해당 플레이어가 초록/빨강을 직접 선택해야 합니다.
- 오른쪽 메인 영역의 **최근 카드 전달**에는 보낸 사람 → 카드(공개된 앞면 또는 비공개 뒷면) → 받은 사람 및 해당 시간 칩 반응이 표시됩니다.
- **턴별 전달·피드백 기록**에는 모든 턴의 공개 정보를 역순으로 남깁니다. 다른 사람에게 숨겨진 카드 정보는 보여주지 않습니다.
- 플레이어 패널에도 해당 플레이어의 가장 최근 피드백 칩이 표시됩니다.
- 구버전 서버가 실행 중이면 터미널에서 Control+C로 종료한 뒤 새 압축 파일 폴더에서 다시 실행해야 합니다. 브라우저 새로고침만으로는 서버 로직이 바뀌지 않습니다.
- 변경 후 이전 방은 메모리 내 데이터이므로 새 게임 방에서 테스트하는 것을 권장합니다.


## v0.4 — 플레이 화면 UI/UX 재구성 (2026-10-26)

**서버 게임 규칙 로직은 v0.3과 동일합니다.** `static/app.js`, `static/style.css`, `static/index.html`만 변경했습니다.

- 최상단: 서울 미션 번호와 현재 특수 규칙만 유지. 미션 카드 앞·뒷면 이미지는 '미션 카드' 팝업으로 이동.
- 중앙 상단: 네 플레이어를 2×2 보드로 압축. 캐릭터 이미지, 남은 시간 칩 수, 카드 수와 공개 카드, 최근 수신 칩을 표시.
- 중앙 중단: 현재 행동과 가장 최근 전달(보낸 사람 → 실제 공개 상태의 카드 → 받은 사람 및 초록/빨강 시간 칩)을 하나의 영역에서 표시.
- 중앙 하단: 내 손패와 행동 버튼을 묶음. 데스크톱에서는 화면 아래쪽에 고정, 작은 화면에서는 일반 흐름으로 표시.
- 오른쪽: 턴별 전달 기록 하나만 표시하고, '전체' 또는 특정 캐릭터의 **받은 기록**으로 필터링. 카드 공개 조건이 없으면 카드 뒷면만 표시.
- AI 턴: 중앙의 버튼 클릭 1회에 카드 전달 1회. AI의 연속 턴을 자동 실행하지 않음.
- 선택 흐름: 내 카드 선택 → 플레이어 카드 안의 '이 사람에게 전달' 클릭 → 내 손패 영역의 '카드 전달하기'.
- 준비 단계: 사람/AI 방 구성, 캐릭터 선택, 서울 02/03의 공개 단계 유지.
- 종전 중복 '미션 로그' 패널을 메인 화면에서 제외. 개발 화면 확인 링크는 도움말 안에 배치.
- API 데이터는 기존의 `turn_events`를 사용. 새로운 숨겨진 손패 정보는 추가하지 않음.
- 상태 폴링에서 변화 없는 데이터를 받으면 불필요하게 화면 전체를 갱신하지 않아 선택 상태와 기록 스크롤을 유지.

### 기존 폴더만 업데이트하기

1. 서버 실행 터미널에서 `Control+C`로 종료.
2. **UI 패치 ZIP**을 풀고 파일 3개 (`app.js`, `style.css`, `index.html`)를 모두 복사.
3. 기존 `sort5_seoul_web/static/` 폴더 안에 붙여넣기하여 **이 세 파일만 대치**. `assets` 폴더는 유지.
4. 기존 프로젝트 폴더로 이동해 `python3 -m uvicorn server:APP --host 0.0.0.0 --port 8000` 실행.
5. 크롬에서 새로고침. 필요하면 `Command+Shift+R`.

## v0.5 — 스크롤 없는 턴 진행 조작 (2026-10-26)

### 무엇이 바뀌었나요?

- **AI 턴 진행하기**를 화면 가운데 아래쪽의 일반 스크롤 영역에서 제거하고, **화면 하단 고정 조작바**로 옮겼습니다. 페이지가 길어져도 AI 진행 버튼은 계속 보입니다.
- 하단 조작바에는 현재 턴을 맡은 AI와 직전 카드 전달·칩 반응이 함께 표시됩니다. **클릭 한 번에 AI 카드 전달 한 번**만 진행하는 기존 방식은 유지됩니다.
- 사람 턴의 **카드 전달**, 카드 수신 후 **초록/빨강 칩 선택**, 캐릭터 선택 및 미션 진행 버튼도 같은 하단 조작바에 유지됩니다.
- 데스크톱의 충분히 넓은 화면에서는 캐릭터 4명을 2×2에서 **가로 4열**로 간결하게 표시합니다. 따라서 `현재 상황` 영역이 위쪽으로 올라옵니다.
- 오른쪽 추리 기록은 독립 스크롤이며, 기록 보기를 위한 데이터·비공개 카드 정책은 그대로 유지합니다.
- 작은 화면에서도 하단 조작바는 고정되며, 자신의 카드는 수평 스크롤로 확인합니다. 페이지 맨 아래 콘텐츠가 조작바에 가려지지 않도록 여백을 추가했습니다.

### 기존 폴더 업데이트

1. 실행 중인 서버에서 `Control + C`로 종료합니다.
2. `SORT5_Seoul_UI_Update_v05.zip`을 압축 해제합니다.
3. `app.js`, `style.css`, `index.html` 세 파일만 복사합니다.
4. 기존 프로젝트의 `sort5_seoul_web/static/` 폴더에 붙여넣고 **대치(Replace)**합니다. `static/assets/`는 그대로 둡니다.
5. 기존 `sort5_seoul_web` 폴더에서 `python3 -m uvicorn server:APP --host 0.0.0.0 --port 8000`로 서버를 실행합니다.
6. 크롬에서 `http://localhost:8000`을 열고 `Command + Shift + R`로 강력 새로고침합니다. 브라우저 캐시를 위한 파일 버전을 `?v=05`로 올렸습니다.

이번 버전은 **UI 파일 3개만 바뀝니다.** 서버/AI 전략/미션 판정에는 변화가 없습니다.
